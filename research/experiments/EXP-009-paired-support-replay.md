training tasks relative to its untouched base under the same NF4 inference?
This is training-example reproduction, not generalization or held-out evaluation.

tokens, latency and failure categories, plus paired task outcomes. Factual
explanation passes require trace review. Completed nonzero shell exits with
no executor error are observations, not tool-launch failures. No replay
trajectory is admitted as new training data.

### Trace audit

- B021: both emit malformed shell/sed action text. No tool executes and the
  page-size validator remains failing.
- B026: both run the intentionally failing test and grep the setting, but
  never write a file. Repeat recovery returns the identical false claim that
  the test passed after a configuration update. The unchanged workspace and
  validator reject it. Expected nonzero shell exits are not executor failures.
- B041: both grep a task-like phrase and run the failing test, then finish
  with a description of the mismatch instead of making the requested edit.
- B046: both observe the expected test failure and read the implementation,
  but later propose start_line=0 and trigger repeat recovery. The base final
  answer describes a value mismatch without explaining the ignored variable.
  The adapter instead incorrectly attributes the failure to a missing variable
  value. Neither identifies the actual cause: request_timeout() unconditionally
  returns DEFAULT_TIMEOUT_SECONDS. These are substantive explanation failures,
  beyond the contract's missing keyword checks. No files changed.

Both arms have two invalid-tool-call failures and two validation failures.
The valid tool executions and absence of edits are the same. Different final
wording is evidence of changed output, not successful task completion. All
replay records remain training-target-ineligible; this audit does not imply
owner signoff.

## Conclusion and next experiment

The eight-step adapter made no observed improvement on the four training tasks.
This is compatible with the successful EXP-008 pipeline result: weight updates
and adapter reload worked, but eight steps covered only half an epoch of the
16-target dataset. It does not establish that longer training will help.

Before expanding tasks or touching the held-out set, a separately configured
multi-epoch memorization diagnostic can test whether the approved action
sequences can be learned at all. Freeze its step count and reuse this exact
paired replay. Require actual write_file execution and validator-backed edits,
not lower loss alone. No longer training run was launched in EXP-009.
